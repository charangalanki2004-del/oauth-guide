# Verification log

How this was done: five guides were generated by the agent (Groq, `openai/gpt-oss-120b`), then
audited two ways. (1) Three real registrations, timed, with what the provider's own screens said
recorded in `data/tested/<slug>.json` and merged into the guide as the *tested* tier.
(2) Spot-checks of sourced claims against the cited pages. "Corrected" below means the real
screen or the cited page contradicted the generated text.

## Apps audited

### GitHub (`github`) — tested
- **Real setup attempt:** 2026-10-22, ~5 min. Settings → Developer settings → OAuth Apps →
  "Register a new OAuth app". Client ID shown at once; secret via "Generate a new client secret".
  No review, no wait, Marketplace listing optional.
- **Confirmed:** anyone with an account can register; no approval gate; access tokens expire
  (8 h) with refresh tokens only when "Expire user access tokens" is enabled; implicit grant not
  supported; device flow exists.
- **Corrected:**
  - "one redirect URI per app, exact match" → the form allows **up to 10 redirect URIs** and an
    optional **"Allow wildcard matching"** checkbox (off by default).
  - "callback must be HTTPS" → `http://localhost:8000/callback` accepted with no warning; HTTPS is
    never mentioned on the form.
  - "expiring tokens enabled by default" (Gemini run) and "tokens never expire" (first Groq run)
    → **both wrong**: the checkbox exists and is **off by default**.
  - one run invented "sensitive scopes trigger verification" → no such thing exists; the prompt
    now forbids inventing review steps.
- **Could not verify:** PKCE support for OAuth Apps (not on the form; docs the agent read do not
  mention it). Setup-time guess of 15–60 min was replaced by the measured 5 min.

### Slack (`slack`) — tested
- **Real setup attempt:** 2026-10-22, ~8 min plus ~2 min to create a free workspace.
  api.slack.com/apps → "Create new app" → Blank app → name + workspace → scopes → done.
  The wizard **creates and installs the app into the chosen workspace in one go**.
- **Confirmed:** self-service; bot scopes chosen at creation; redirect URLs under OAuth &
  Permissions; credentials under Basic Information.
- **Corrected:**
  - gate `unknown` → **`marketplace_only`**: the only review path is the Marketplace
    "Prepare & Submit" sidebar (App Listing, Review scopes, Security and compliance, Testing
    information, Automated checks).
  - "From scratch" option in docs/tutorials → **no longer exists**; the dialog offers templates,
    a manifest upload, "Blank app", or the Slack CLI.
  - redirect matching: the page says a request URL "must (partially) match" a saved one →
    prefix matching, not exact; `http://localhost` accepted.
- **Could not verify:** token expiry (nothing on the screens; the sourced claim stands).

### Google Workspace (`google-workspace`) — tested
- **Real setup attempt:** 2026-10-22, ~13 min including project creation, personal Gmail
  account. "Google Auth Platform" (renamed consent screen) → Create branding (4-step wizard,
  audience External) → Clients → Web application → redirect URI → created; JSON download offered.
- **Confirmed (by the console's own text):** External apps start in **Testing**; only listed test
  users can authorise; "Allowed user cap prior to app verification is **100**, and is counted over
  the **entire lifetime** of the app"; "Verification is not required since your app is configured
  with a testing publishing status"; scopes are classed non-sensitive / sensitive (/ restricted),
  which decides what verification needs. Gate `review_for_scopes` is right.
- **Corrected:**
  - difficulty 5 → **4**: the measured 13-minute setup replaced the model's longer guess; the
    verification burden is real but only applies at publish time.
  - menu names: guides and most docs say "OAuth consent screen"; the console now says
    "Google Auth Platform" with Branding / Audience / Clients / Data access / Verification centre.
- **Found, not in any docs the agent read:** the client form's **"Use this client for an
  AI-powered agent"** checkbox ("Select this if your client uses Google MCP tools… use separate
  OAuth clients for each"), and the note that settings "may take five minutes to a few hours to
  take effect".
- **Could not verify:** verification turnaround time (not shown anywhere before submitting).

### QuickBooks Online (`quickbooks-online`) — sourced only, **known weak**
- **What happened:** Intuit's docs on `developer.intuit.com` are JavaScript-rendered; the
  rendering fallback recovered "Set up OAuth 2.0", but `help.developer.intuit.com` (where the
  app-assessment / production-keys requirements live) returned no text even through the proxy.
- **Result:** the model, told not to invent review steps, reported no documented review → level 2,
  gate `unknown`, 0 sourced claims. From general knowledge this is wrong (QBO requires an app
  assessment before production keys), but nothing the agent could read supports it, so the guide
  honestly says `unknown` and `low` confidence rather than asserting it.
- **Corrected / could not verify:** not audited further; kept in the demo as the example of what
  the evidence tiers are for.

### Shopify (`shopify`) — sourced only
- **Confirmed by spot-check:** official pages read were the right ones ("About app
  authentication", "Authenticate a standalone or API-only app", "Authenticate an app for stores
  in your organization"); 15 of 24 claims sourced.
- **Could not verify:** the level-5 score rests on the review artifacts the model listed; no
  Partner account was created, so wait times and the exact listing requirements are unverified.

## Patterns noticed

- **Provider UIs drift faster than docs.** All three real registrations differed from the docs
  the agent read: GitHub's multi-redirect-URI form, Slack's new wizard (no "From scratch"),
  Google's renamed console. A guide generated from docs can be right about rules and wrong about
  button names.
- **Models fill gaps with plausible OAuth folklore** ("HTTPS required", "exact match", "scope
  verification"). The citation validator kept those at *inferred*/*unknown*, which is exactly
  the tier that told us where to look.
- **Which three pages get read decides everything.** Keyword ranking picked sidebar links into
  the wrong product (GitHub Apps vs OAuth Apps, Marketplace vs Cloud Console); letting the model
  choose the reading list from titles/snippets fixed Google from 0 to 20 sourced claims.
- **Approval wait times are never on a provider's pages.** Every guide has them as inferred or
  unknown; only a real submission would tell.
- **Free-tier budgets shape the agent.** Groq's 8k tokens/minute forced a prompt budget, a
  three-page reading list and an output cap; the pick step and link-following exist because
  three pages have to be the right three.
